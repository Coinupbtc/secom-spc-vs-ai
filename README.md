# secom-spc-vs-ai (v0)

**On real fab data with a time-ordered holdout and a calibrated 1% false-alarm budget, neither control charts nor ML caught failing runs better than doing nothing, and the Phase I limits over-alarmed 1.8–4.2× their 1% target on later passes. Re-baselining is the obvious next test (not done here).**

**Question:** on real semiconductor fab data, do machine-learning anomaly detectors catch failing production runs better than
classic statistical process control (SPC) charts at the same false-alarm budget?

**Who this is for:** a process or quality engineer deciding whether ML alarms beat control charts before trusting them.
That means comparing at an equal, calibrated false-alarm rate on a time-ordered holdout, with a cost view and with "where to look" contribution plots.

Data: [UCI SECOM](https://archive.ics.uci.edu/dataset/179/secom), 1,567 production runs, 590 anonymized sensor signals,
pass/fail label + timestamp, collected Jul–Oct 2008. Real data only, nothing synthetic.

**Analysis plan frozen before the test block:** split, metrics, limits, cost ratio, and decision rule are in [`PREREGISTRATION.md`](PREREGISTRATION.md),
committed and tagged before any test-block run was scored. The repo is the only witness to that timing, so the real safeguard is
[`DEVIATIONS.md`](DEVIATIONS.md), which logs everything that touched the data before the freeze and every change after it.

## Expected outcome (written into the plan before running)

Control charts may well tie or beat ML here, and no method may beat "never alarm" on cost. Either outcome would be the finding, not a failure.
The gradient-boosting row is a **supervised reference (uses labels)**, not a competitor and not a ceiling.

## Reproduce

```bash
pip install -r requirements.txt   # exact pins; results were produced with Python 3.12.13
make all                          # = python -m secom.data && python -m secom.run && python -m secom.report
```

`make all` downloads the zip from UCI, checks it against the SHA-256 values in `data/MANIFEST.json`, and runs every method with fixed seeds
(the planned analysis takes well under a minute; with the post-hoc checks the total is about 5–10 min on CPU). It writes `results/results.json` and regenerates
`figures/*.png` and every table below from that JSON.

How to read it:
- **Detection rate** = share of the 28 test fails that alarmed on the failing run itself. **False-alarm rate** = share of test passes that alarmed.
- **ARL0** = average number of passing runs between false alarms. Bigger is better: it's how often an engineer gets pulled for nothing.
- **ARL1 / delay** = runs from a fail until the first alarm (delay 0 = alarmed on that run). At a ~1% false-alarm rate, *some* alarm shows up within about 100 runs anyway,
  so delay only means something next to ARL0.
- **AUROC** comes with a stratified bootstrap 95% CI (added post-hoc). A CI that includes 0.5 means "indistinguishable from chance."
- **Cost** = (R·missed fails + false alarms) / test runs, with **R = 10 as an assumption**, not a measured fab cost. Compare each row to *never alarm*.

### What the numbers say (v0, single time-ordered split)

- **No method detected fails better than chance at a calibrated 1% false-alarm budget.** T², SPE and the autoencoder caught 0 of 28 test fails, Isolation Forest caught 2,
  and the supervised reference caught 1. Every AUROC's bootstrap 95% CI includes 0.5. T², SPE and the autoencoder (AUROC 0.42–0.47) are
  **indistinguishable from chance**, and so are Isolation Forest and the supervised reference.
- **Decision rule from the plan:** on point estimates, Isolation Forest beats the better of T²/SPE on both detection (2/28 vs 0/28) and cost at R = 10 (0.4434 vs 0.4673).
  But the 95% Wilson intervals overlap almost completely (0.02–0.23 vs 0.00–0.12), so the plan's rule calls this **not decisive**: a tie at "barely works."
- **Versus doing nothing:** at R = 10, "never alarm" costs 0.4466. Isolation Forest (0.4434) is the only method below it, by about 2 cost units over 627 runs, which is noise.
  The supervised reference (0.4482) does not beat it.
- **The limits over-alarmed on later passes.** Every model fit on Phase I runs alarms on test passes more often (1.8–4.2%) than its 1% target, even with limits calibrated on held-out
  Phase I passes. Textbook parametric T²/SPE limits were **16× and 24× too tight** on the Phase I calibration block. A post-hoc random-holdout check (below) shows
  that most of that gap appears even with no time separation, which points to high dimension, non-normality, and imputation. Scores then jump much further in the test block,
  which is consistent with a later process shift on top of that.
- **The shop-floor chart wall drowns.** I-MR with all Western Electric rules on 10 sensors alarms on every test run. Rule 4 (eight points on one side of the Phase I mean)
  fires on all 627 test runs. A post-hoc check shows this is **not** an imputation artifact: under 2% of rule-4 hits involve a median-imputed point, and excluding
  imputed points still alarms on every test run. Rule 1 alone catches 12/28 fails but also flags 37% of passes.
- **The supervised reference doesn't rescue it.** With Phase I labels, gradient boosting reaches AUROC 0.598 and 1/28 detections. A better supervised model might do more.
  But with a static model trained on earlier runs, these fails are not separable from passes in these sensors.

**Cost sensitivity, one line:** with thresholds fixed at α = 1%, "never alarm" is cheapest at R = 1 and 5, Isolation Forest is narrowly cheapest at R = 10 and 20,
and "always alarm" beats every method at R = 50. No method wins across the sweep.

**Labeled post-hoc:** these were added after the test block was scored, in response to review. They don't change any planned number.

**1. Are the textbook T²/SPE limits too tight because of drift or because of dimension?** A random 25% of the Phase I-fit passing runs is held out (no time separation), preprocessing + PCA are refit on the other 75% (k = 101–106 PCs), and the ratio empirical 99th percentile / textbook 99% limit is measured on each block by the same refit model (20 seeds; median, with min–max):

| statistic | random holdout (same period) | Phase I calibration (later) | test passes (latest) |
|---|---|---|---|
| T2 | 11.8× (3.5–49.7); FAR at textbook limit 6% | 11.5× (10.7–89.6); FAR at textbook limit 50% | 91.9× (81.2–935.6); FAR at textbook limit 85% |
| SPE | 48.7× (15.2–257.3); FAR at textbook limit 93% | 83.1× (20.5–1564.5); FAR at textbook limit 98% | 381.5× (81.7–13490.4); FAR at textbook limit 100% |

For the planned model, the ratios on the calibration block were 15.9× (T²) and 23.7× (SPE), and on test passes 121.0× and 80.2×.
Reading rule (written before running): T² → *high dimension / non-normality / imputation is a major cause on its own*; SPE → *high dimension / non-normality / imputation is a major cause on its own*. The limits are already far too tight on a random same-period holdout, so the 16–24× gap is **not** evidence of drift by itself: high dimension (n ≈ 420–560 passes, ~440 sensors, ~100 PCs), non-normal sensors, and imputation produce most of it. The further jump from the random holdout to the test block is consistent with a later process shift on top. v0 does not attribute it more precisely.

**2. Is Western Electric rule 4 an imputation artifact?** Of 2555 rule-4 hits (sensor × test run) across the 10 I-MR sensors, 49 (1.9%) have a median-imputed point in their 8-point window. With rule 4 evaluated on observed points only, the WE-rules chart still alarms on 599/599 test passes and 28/28 fails. So rule 4 is not an imputation artifact: these sensors sit on one side of their Phase I mean for long stretches of the test block.

**3. Random split vs time-ordered split, same code.** Shuffling the runs before the same 626/314/627 split (10 seeds, 38–54 test fails) vs. the time-ordered split (28 test fails):

| method | time-ordered AUROC | random-split AUROC, mean (min–max) |
|---|---|---|
| PCA Hotelling T² (classic) | 0.424 | 0.557 (0.491–0.598) |
| PCA SPE/Q (classic) | 0.474 | 0.568 (0.520–0.623) |
| Isolation Forest (ML, unsupervised) | 0.554 | 0.560 (0.478–0.643) |
| Autoencoder MLP (ML, unsupervised) | 0.441 | 0.558 (0.504–0.633) |
| Gradient boosting, supervised reference (uses labels) | 0.598 | 0.673 (0.608–0.746) |

Post-hoc: the supervised reference scores AUROC 0.67 on average with a random split vs 0.60 time-ordered. Shuffling lets the model train on runs from the same weeks it is tested on, so random-split SECOM numbers flatter every method. A deployed monitor only ever sees the past.

## Methods (details in PREREGISTRATION.md)

- **Classic SPC:** PCA fit on Phase I passing runs → Hotelling T² and SPE/Q charts, with 99% limits from held-out Phase I calibration passes
  (textbook F / Jackson–Mudholkar limits also reported). Plus univariate **I-MR charts** on the 10 sensors ranked most fail-related on Phase I-fit only,
  with Western Electric rules 1–4 + MR-chart signal. Those are reported uncalibrated, the way a shop-floor chart wall runs.
- **ML, unsupervised:** Isolation Forest (500 trees) and a small MLP autoencoder (64-16-64), both fit on Phase I passing runs only. Thresholds come from the same
  99% calibration rule as T²/SPE.
- **Supervised reference (uses labels):** histogram gradient boosting trained on Phase I-fit runs *with* pass/fail labels. It's one reference model, not a ceiling
  and not a fair competitor: in a fab, labels arrive late and fails are rare. (The frozen plan calls it an "upper-bound reference"; renamed after review, see DEVIATIONS.md.)

## Limitations (plainly)

- **Old, small, single-source data.** One public dataset from one fab, from 2008, covering about three months. Results may not carry over to other tools, products or fabs.
- **Anonymized sensors.** No physical meaning, units or process step is known, so contribution plots can't be checked against engineering knowledge.
- **Class imbalance and tiny test positives.** 104 fails total and only 28 in the test block, so each test fail moves the detection rate by about 3.6 points.
  The confidence intervals are wide. Read differences of a few detections as noise.
- **Label semantics.** "Fail" is an in-house line-testing outcome for the run. It isn't a confirmed root-caused excursion, and many fails may not be visible in these sensors at all.
- **Static Phase I model.** Limits from one early baseline go stale. Textbook limits also don't hold in this many dimensions (see the post-hoc check).
  Rolling-origin or re-baselined evaluation is the obvious v1 and is not done here.
- **Single split, single seed** for the planned analysis. No repeated evaluation in v0.
- **Cost ratio is assumed** (R = 10), so a sweep over R = 1–50 is shown instead of claiming one true number.

## Layout

```
secom/data.py         download + checksum manifest + time-ordered loader
secom/preprocess.py   missing-value audit, Phase-I-only imputation/scaling
secom/methods.py      PCA T²/SPE (+contributions, parametric limits), I-MR + WE rules, IsolationForest, autoencoder, gradient boosting
secom/metrics.py      detection rate, FAR, ARL0, delay/ARL1, cost, Wilson CIs, AUROC bootstrap CI
secom/run.py          runs everything -> results/
secom/exploratory.py  post-hoc checks (random-holdout limit ratios, random-split AUROC)
secom/report.py       figures/ + README tables from results/results.json
scripts/identity_guard.py  generic identifier check; patterns/keys live outside the repo, skipped when not configured
```
